Exact interface used:
  const Fraction = require('../vendor/fraction.cjs');
  const value = new Fraction(BigInt(card));
  value.add(other), value.sub(other), value.mul(other), value.div(other)
  value.equals(24n)
Fields s (sign), n (nonnegative numerator), d (positive denominator) are BigInt.
The two-argument constructor new Fraction(1n, 3n) also works. toFraction() gives
an exact fraction string. Arithmetic returns reduced fractions. Do not use
valueOf(), floating-point inputs, approximate simplify(), or numeric coercion
for F3 decisions. The upstream Number fallback at lines 32-33 is deliberately
blocked by a native-BigInt guard before require() in tools/generate-24.cjs.

Actual reuse: tools/generate-24.cjs calls this library for all solver arithmetic
and exact equality. Pair reduction, expression construction, enumeration and
data formatting are MindOrbit code, not supplied by Fraction.js. Every merge
consumes two disjoint subexpressions; addition/multiplication need one order,
subtraction/division retain both orders, and zero divisors are skipped. Failed
states and equal results are deduplicated using reduced rational values only.

window.MindOrbit.twentyFourVersion = '1'. The existing namespace is preserved.

All 495 nondecreasing four-card multisets in 1..9 are included exactly once:

The generated script contains no runtime Fraction.js or native-BigInt dependency.

Verification: the Node test has its own signed BigInt rational arithmetic and

Initial adaptation assessment (reference only; no copying was ultimately needed):
- Lines 1-8: sixteen symbol entries form eight pairs. The Math.round random
  splice is biased; replace with an unbiased Fisher-Yates shuffle driven by
  the host random source. Use locally generated, consistent symbols instead
  of the unaudited Font Awesome class names.
- Lines 10-26: DOM bindings and mutable globals must become session-local state
  with host-managed listeners. Declare all variables; do not preserve implicit
  globals or the hard-coded #attempts/#points DOM contract.
- Lines 40-54: timer starts on first click and attempt increments on first flip.
  A3 instead starts its monotonic clock when the board becomes playable after
  preparation and counts one step only on a valid SECOND distinct card flip.
  Same-card, already-matched, locked, expired and terminal inputs are no-ops.
  Do not copy the same-card listener-removal side effect at lines 48-49.
- Lines 56-62: reuse/adapt the equality comparison, matched-pair retention and
  reset of the active selection. Prefer explicit symbol IDs and matched state
  over firstChild.classList[1] and per-card removeEventListener bookkeeping.
- Lines 64-79: discard all upstream score multipliers. Report matchedPairs M,
  steps P and elapsed time t to the host for the specified A3 score:
  S(100*(M/8)*(0.7*M/max(P,1) + 0.3*clip((120-t)/90,0,1))). t is in seconds.
- Lines 81-99: adapt the two-card mismatch lock and delayed simultaneous cover.
  Replace the 1000 ms timeout with the specified 700 ms, and use an explicit
  lock plus a host-owned cancellable callback rather than bulk listener removal
  and reattachment. No third flip during mismatch feedback, and no extra 500 ms
  feedback stage. Cancel pending cover callbacks on finish, timeout or abort.
- Lines 30-38 and 40-45: replace Date/rounded seconds/interval logging with the
  host monotonic clock and absolute 120000 ms deadline. Complete once at eight
  pairs or deadline; an unfinished single flip is not a step. Ignore obsolete
  callbacks after destroy and never write scores/storage directly from A3.
